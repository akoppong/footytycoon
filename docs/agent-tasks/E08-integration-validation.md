# E08 — Validate integrated policy differences

Depends on: E01 and integrated E07. Type: diagnostic/testing integration. Read [shared instructions](README.md), AGENTS.md and the preregistered E00 contract.

## Outcome

We know whether the implemented mandates produce real tradeoffs, preserve save/financial safety, and provide a usable build for player evaluation.

## Work and ownership

- Extend the E01 diagnostic path minimally to run E00's fixed seed list and policy matrix from E01B's documented starting checkpoints. Include a default/default control, a manager-only change, a director-only change, and the combined approach. For each seed, load the same migrated starting checkpoint for every policy; exclude the identical preparation period from measured outcomes. Hold capital plan and owner approval rules constant in these causal comparisons; report additional strategy bundles separately.
- Capture the actual command trace, recommendation opportunities, approvals, realized signings, wages/commitments, cash, points, youth appearances and development. Verify both director modes' selected terms through real production previews/approval paths; E01B's diagnostic alternate checks alone are insufficient. Label cases with no eligible alternative. Do not drop unfavorable or no-op seeds after looking at outcomes.
- Compare loaded versus uninterrupted execution with identical commands. Validate policy change while a bid is pending, season rollover, no-candidate worlds, terminal states and fault-injected publication.
- Run applicable solution tests, formatting/build checks, Desktop smoke and small end-to-end timing samples on a named machine. Record separate core, query, preview, autosave and advance timings; do not mislabel historical numbers as current measurements.
- Write `docs/OWNER_MANDATE_EXPERIMENT_RESULTS.md` with raw artifact paths, provenance, limitations, pass/revise outcomes and unresolved player questions.

## Boundaries

No tuning during the fixed comparison, no claim of statistical proof from a small sample, no 50-season campaign and no silent bug repairs mixed into evidence. File a bounded repair task for a defect, obtain review, then rerun only affected evidence plus the necessary integrated gate.

## Acceptance

Results distinguish altered rankings, altered real actions and altered season outcomes. Controlled examples demonstrate intended staff effects; sampled runs disclose frequency and uncertainty. Replay/financial invariants pass or failures are explicit. E00 thresholds are reported unchanged, with any proposed next-run revisions clearly separated. An independent reviewer checks code/diagnostics and sampled raw results. Deliver a reproducible playable revision for E09; technical success alone does not pass the product gate.
